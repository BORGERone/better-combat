# Hackers 'n Slashers — патч 2.0-beta2.5 (сборка под сборку с Mallard Guard)

Готовый файл: **`hackersandslashers-2.0-beta2.5-fixed.jar`** (Minecraft 1.21.1 / NeoForge, Java 21).
Просто замените старый `.jar` в папке `mods/`.

## 1. Исправлен рывок (Dash / Рывок на X)

**Проблема:** если зажать `W` + `A`/`D` (вперёд + вбок) и нажать рывок, вектор складывался по двум осям
(`forward + strafe`), поэтому импульс получался `0.75 × √2 = 1.0607` вместо `0.75` — рывок улетал
**на 41% дальше**, и по диагонали можно было «прыгать» через большее расстояние, чем по прямой.

**Исправление.** В `CombatParkourManager.calculateDodgeVector` вектор ввода нормализуется перед
масштабированием. Проверено на реальном байткоде:

| Направление | Было (импульс) | Стало (импульс) |
|---|---|---|
| Вперёд | 0.7500 | 0.7500 |
| Вперёд + влево | **1.0607** | **0.7500** |
| Вперёд + вправо | **1.0607** | **0.7500** |
| Назад + влево | **1.0607** | **0.7500** |
| Только влево | 0.7500 | 0.7500 |
| Перекат вперёд + влево | 1.2021 | 0.8500 |
| Без ввода клавиш | 0.6000 | 0.6000 |

Тот же фикс работает и на серверной стороне, потому что вектор импульса отправляется серверу
в пакете `C2S_PacketTriggerPlayerDodge` уже нормализованным.

## 2. Совместимость с Mallard Guard: стамина за блоки и парирования

Раньше: Mallard Guard отлично работал вместе с модом, но **за его блоки/парирования стамина не
тратилась**. Теперь:

* **Идеальное (perfect) парирование — бесплатно.** Это единственный случай, когда стамина не тратится.
* **Обычный блок мечом (tool block) — тратит стамину** (`2.0` ед. по умолчанию = одна полная ячейка HUD).
* **Смертельный блок** (урон, который бы вас убил) — тратит больше (`4.0` ед.).
* **Обычное (тайминговое) парирование** — тратит `2.0` ед.
* **Блок щитом** — по умолчанию бесплатный (`mallard_shield_block_costs_stamina = false`).
* **Нет стамины — нет защиты.** Если стамины не хватает на блок, стойка ломается, и удар проходит
  как обычный (можно отключить: `mallard_guard_requires_stamina = false`).

Технически используется «мост» на рефлексии (`compat/mallardguard/MallardGuardBridge`): мод читает
фазу стойки Mallard Guard (1 = идеальное парирование, 2 = обычное парирование, 3 = блок, 4 = блок
щитом) до расчёта урона и списывает стамину только если блок/парирование реально состоялись.
**Если Mallard Guard не установлен — мост полностью отключается и ничего не стоит.**

## 3. Щит во второй руке: парирования выключены, ПКМ = ванильный блок щитом

Если в **левой руке лежит щит**:

1. Механика парирований Hackers 'n Slashers **выключается** (парирование, начатое до взятия щита,
   сбрасывается; сервер это тоже проверяет на тике).
2. Mallard Guard **не может парировать/блокировать** за игрока — его стойка принудительно
   сбрасывается, и урон считается как без стойки.
3. **ПКМ блокирует щитом как в ванили.** Чтобы Mallard Guard не перехватывал правую кнопку,
   мод при старте сервера добавляет `minecraft:shield` и `#c:shields` в `shieldBlacklist` Mallard Guard
   (это видно в логе: `Mallard Guard: shields now use vanilla blocking`).

Если автоматика не сработает (другая версия Mallard Guard), сделайте это вручную в
`config/mallard_guard/server.toml`:

```toml
[items]
	shieldBlacklist = "minecraft:shield,#c:shields"
```

## 4. Новые настройки в конфиге

Файл: `saves/<мир>/serverconfig/hackersandslashers-server.toml`
(или `defaultconfigs/hackersandslashers-server.toml`, чтобы применить ко всей сборке).

```toml
["Block Stamina & Shield Settings"]
	enable_mallard_guard_compat = true          # интеграция стамины с Mallard Guard
	mallard_block_energy_cost = 2.0             # стамина за обычный блок мечом (1 ячейка = 2.0)
	mallard_block_fatal_energy_cost = 4.0       # стамина за смертельный блок
	mallard_parry_energy_cost = 2.0             # стамина за обычное (не идеальное) парирование
	mallard_perfect_parry_refund = 0.0          # бонус стамины за идеальное парирование (0 = просто бесплатно)
	mallard_guard_requires_stamina = true       # без стамины стойка ломается
	mallard_shield_block_costs_stamina = false  # тратить ли стамину за блок щитом
	offhand_shield_disables_parry = true        # щит в левой руке отключает парирования
	offhand_shield_forces_vanilla_blocking = true # ПКМ со щитом = ванильный блок
	disable_parry_with_mallard_guard = false    # true = HnS-парирование полностью уступает Mallard Guard
```

Шкала стамины не изменилась: всего `10.0` (5 ячеек × `2.0`), полная шкала = `10` секунд зацепа.

Ранее добавленная секция зацепа осталась без изменений:

```toml
["Grapple & Parkour Settings"]
	enable_grapple = true
	min_grapple_target_height = 1.6
	min_grapple_target_width = 0.5
	allow_grapple_babies = false
	grapple_energy_per_second = 1.0
	grapple_entity_blacklist = ["minecraft:armor_stand"]
	grapple_entity_whitelist = []
```

## 5. Что проверено

* Все изменённые классы собраны компилятором **ECJ 3.46.100** под **Java 21** (major version 65).
* `-Xverify:all` на OpenJDK 21: классы загружаются и проходят проверку байткода.
* ABI-аудит: ни один публичный метод/поле `ServerConfig` и `CombatParkourManager` не потерян.
* Проверены все внешние JVM-дескрипторы: новые ссылки только на реально существующие методы
  (`Entity#getUUID`, `Player#isCreative`, `PlayerList#getPlayers`, `ModList#getLoaded`,
  `LivingIncomingDamageEvent#isCanceled/setAmount` и т. д.).
* 41 автоматический тест (значения конфига, нормализация рывка, стоимость блоков по фазам,
  определение щита в левой руке, безопасная работа без Mallard Guard) — все пройдены.
* Сравнение с исходным `.jar`: диагональ была `1.0607`, стала `0.7500`.
